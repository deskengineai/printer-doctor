Printer Doctor

One script that finds out why a Windows PC won't print, explains it in plain English, shows exactly what it would change, fixes it only after you approve, and can roll back if anything breaks. Works with any printer brand.

Beta. Diagnosis, preview and reports have been run on a real printer. The actions that change settings have only been tested in a harness so far. Run -Preview first; every change is backed up and -Rollback undoes port and SNMP changes.

.\printer_doctor.ps1 .\printer_doctor.ps1 -Preview .\printer_doctor.ps1 -Commit .\printer_doctor.ps1 -Select .\printer_doctor.ps1 -Rollback .\printer_doctor.ps1 -Report .\printer_doctor.ps1 -Report-Public

What it checks

Diagnosis is read-only and runs without admin rights. It checks 14 things across five areas.

Spooler & queue

  • Print Spooler serviceRunning, stopped, or recently crashed
  • Stuck jobsError states, jobs older than 10 minutes, jobs already sent to the printer
  • Offline, paused, unavailableQueue status plus the hidden "Use Printer Offline" flag

Port

  • Port typeWSD, Standard TCP/IP, IPP, USB, or shared printer
  • WSD discovery addressFlags a WSD queue bound to a Wi-Fi Direct address
  • SNMP status pollingWhether it's on, and whether the printer actually answers it
  • Static or changing IPRemembers the printer's hardware address and warns when its IP moves

Network

  • Hostname resolves to an IP
  • Ping
  • Print ports9100 raw · 631 IPP · 515 LPR · 80 web page, whichever fit the port
  • Wi-Fi / Ethernet in useCurrent network name, with -ExpectedNetwork to catch the wrong Wi-Fi
  • Firewall, VPN, network profileDetects a VPN carrying printer traffic, and Public profiles that block discovery

The printer itself

  • Device status over IPPPaper out, jam, door open. Windows can't see these once SNMP is off.

Driver & logs

  • Driver present and intactMissing driver files, generic class drivers, driver from the wrong manufacturer
  • Recent print errorsError codes, destroyed jobs (824), last confirmed print (307). Harmless driver-store noise is filtered out.

How to fix it: five modes

Work through these in order. Only commit, select and roll back change the PC, and each one shows you what it will do before it does anything.

  1. 1Diagnose.\printer_doctor.ps1

    Finds the cause. Read-only, no admin needed.

    no changes
  2. 2Preview-Preview

    Lists every change the fix would make, and what you have to do by hand.

    no changes
  3. 3Commit-Commit

    Applies the whole plan after one approval. Stops at the first failure and shows before vs after.

    changes PC
  4. 3or Select-Select

    Applies only the plan steps you type, e.g. 3 or 2,3.

    changes PC
  5. 4Roll back-Rollback

    If anything breaks, puts the port and SNMP setting back and deletes ports the script created.

    undo

SNMP: kept unless you say otherwise

Windows uses SNMP to ask the printer whether it is online and whether it has paper. Some people rely on those alerts, and SNMP polling is also a common reason for a false "Offline". The script never makes that choice for you.

-Snmp Keep · defaultSNMP stays on
  • If the printer ignores SNMP, the plan tells you to turn on SNMP read access on the printer's web page and check the community name matches.
  • A new port copies the old port's SNMP setting.
  • Moving from WSD: SNMP is turned on only if the printer answers it. Polling a silent printer is what marks the queue Offline.
-Snmp OffWindows stops polling
  • The plan may turn off SNMP status monitoring on the port in use, then restart the spooler (only if nothing is printing).
  • Trade-off: Windows always shows "Ready" and can no longer report paper-out, jams or open covers. The script's IPP check still can.
  • Shown with the evidence before anything changes.

Safety built in

These apply to every mode that changes the PC.

  • Backup first. Before the first change, printer, port and registry settings are saved to backup_<date>\, along with rollback.json, which records the original port, its SNMP setting, and every port the script creates.
  • Nothing outside the plan. Commit and Select do only the listed steps, in order.
  • Stops on the first failure. A failed step is reported as FAILED, never as a success, and the steps after it do not run.
  • Offers rollback when something breaks. If a step fails, or the printer stopped answering on port 9100 after the changes, the script shows the rollback and asks once.
  • Guards printing jobs. It will not change the port or restart the spooler while a job is printing. That is what destroyed a 45-page job (E2).
  • Deleting jobs is always asked separately, even in Commit, because deleted jobs are gone for good.
  • Re-reads before acting. The port and SNMP setting are read at the moment of the change, not from startup, so a port moved earlier in the session or by vendor software is never missed (E10).

Rollback cannot bring back deleted print jobs, and it leaves "Use Printer Offline" switched off.

Single actions

Run with -Fix for a menu of single actions. The menu also has P preview, C commit, S select and R roll back. Actions that match the diagnosis are marked "suggested". Nothing runs until you type Y.

[1]Back up printer settings

Saves the printer, port and print settings as JSON and .reg files, plus rollback.json. Runs automatically before any change.

no changes
[2]Restart the Print Spooler

Refuses while any job is printing. Queued jobs survive a restart, but a job that is mid-print is destroyed.

adminguarded
[3]Clear stuck jobs

Lists the jobs and always asks, even in Commit. Warns when a job has already reached the printer. Removes leftover job files only if normal deletion fails.

adminalways asks
[4]Set printer online

Clears "Use Printer Offline" and resumes the queue. Warns if the printer isn't reachable on the network.

backup first
[5]Re-test DNS and reachability

Re-runs the name lookup, ping, port and route checks.

no changes
[6]Move to a Standard TCP/IP port

Checks that port 9100 answers, creates IP_<address> with RAW printing, then moves the printer onto it. SNMP follows the rules above. The old port is kept.

[7]Open port settings

Opens the printer's Ports tab in Windows.

no changes
[8]Disable SNMP status monitoring

Acts on the port in use right now. Shows the evidence and the trade-off first, and tells you if the printer is answering SNMP, in which case you may want to keep it.

adminguardedbackup first
[9]Escalation report

A Markdown file with the port type, printer IP, ping result, driver, spooler state, error codes and the full diagnosis. Private: includes identifying details.

no changes
[10]Public report

The same report with personal details redacted, safe to post in a forum or GitHub issue.

no changes

Sharing a report

-Report is for someone you trust, such as your IT person. -Report-Public is for anywhere public. It also redacts what prints on screen, because terminal output gets pasted as often as files do.

redactedReplaced with placeholders
  • Document names → <document-1>
  • Username, PC name, domain, C:\Users\… paths
  • Printer name, Wi-Fi and network names, VPN and adapter names
  • SNMP community, GUIDs, emails, \\server names
  • IPs → 172.16.x.x; MACs → vendor prefix only; raw event text → its meaning
keptWhat a helper needs
  • Port type, driver name and version
  • Queue and spooler status
  • Error codes such as 0x800706BE
  • Windows build, firewall and network-profile state

Lessons from past failures

Each rule comes from a real mistake logged in ERRORS.md.

E1 · E13Offline while reachable is a port problem

WSD loses the printer after sleep or a Wi-Fi roam. Here it was also bound to the Wi-Fi Direct address. Printer sleep settings are a red herring.

E2Never restart the spooler mid-print

That destroyed a 45-page job (error 0x800706BE), and the queue looked empty, as if it had printed.

E2An empty queue doesn't mean it printed

Only event 307, "Pages printed: N", confirms a job actually came out.

E3 · E12Toner percentages can be fiction

Third-party cartridges report estimated levels. Judge toner by the printed page.

E4Don't trust the Print Queue window

After a spooler restart it keeps showing old jobs. Close and reopen it.

E5With SNMP off, ask the printer

Windows shows "Normal" even with an empty paper tray. The IPP status check fills that gap.

E10Settings live on the port

Vendor software can move the printer to a new port with different settings. Re-run the doctor after driver updates.

E11Unknown beats a false zero

Without admin rights, counting spool files silently returns 0. The script reports "unknown" instead.

Usage

Changes need PowerShell opened with Run as administrator. If scripts are blocked, run powershell -ExecutionPolicy Bypass -File .\printer_doctor.ps1.

.\printer_doctor.ps1Diagnose only. Asks which printer if there are several.
-PrinterName '<name>'Check one specific queue
-PreviewShow the fix plan. Changes nothing.
-CommitApply the whole plan after one approval (-AutoFix also works)
-SelectApply only the plan steps you pick
-RollbackUndo the changes recorded in the latest backup
-Snmp Keep | OffKeep (default) never turns SNMP off. Off lets the plan turn off Windows SNMP polling.
-FixMenu of single actions, plus P / C / S / R
-ReportWrite an escalation report (private, full detail)
-Report-PublicRedacted report and screen output, safe to post publicly
-ExpectedNetwork HomeWiFiWarn when the PC is on a different Wi-Fi network
-EventDays 14How far back to read the print logs (default 7 days)
-OutDir <folder>Where reports, backups and the IP history go (default: the script's folder)
